# 魚島（Island）設計文件

狀態：雛形完成（2026-11-26，#170、#171、#172、#183、#189 已上線）。父 issue：#169。細節規格寫在各子 issue，本文件只記問題、解法、切分，以及跨 issue 都要遵守的決定；內容以已上線的行為為準。

## 1. 問題

- 族人對同一條魚的叫法、飲食分類、處理方式，各部落不一樣，而且沒有標準答案。
- among 魚頁的「大家怎麼說」（`fish_tribe_responses`）已經能收各部落的說法，但要先登入、要先找到那條魚、一次只看一條魚，願意來填的人不多。
- 沒有登入的人完全看不到「大家怎麼說」，也沒有理由留下來。

## 2. 解法

在同一個網站開一個不用登入的新前端「魚島」（`/island`），主要對象是 50 歲以下、可以活潑一點：

1. 進來先設一個角色（名字＋部落），就能開始玩。
2. 畫面是蘭嶼的平面地圖，上面有 6 個部落。角色從自己的部落出發，點哪個部落就走到哪裡。
3. 走進部落是這個部落的「家屋」，有四個地點：主屋、靠背石、曬魚庭院、涼亭。魚分批放在四個地點，每個地點有一位 NPC。
4. 跟 NPC 聊天，NPC 一條一條講這個部落多數人怎麼分類、怎麼處理這條魚；還沒有答案的，NPC 反過來問你。也可以看地點的魚卡清單，自己挑魚。
5. 作答頁先看結果、再選「我來說」；沒有標準答案，答完馬上看到這個部落的結果，想知道是誰答的再點開。

回答寫進 among 現有的同一張表，among 魚頁的「大家怎麼說」會跟著增加。

## 3. 已確認的規則

### 3.1 身分（#170）

| 項目 | 規則 |
|---|---|
| 入口 | `/island`，不用登入；沒有角色的人一律導到角色設定頁 |
| 角色 | 名字（最多 20 字）＋部落，一個帳號一個角色，第一版不能改。名字就是顯示給別人看的名字，想匿名就取暱稱 |
| 訪客 | 沒登入的人設好角色後，系統替他建一個魚島訪客帳號（`users.source = island_guest`），靠瀏覽器記住。清掉瀏覽器資料就找不回這個角色 |
| 已登入 among 的人 | 用原本的帳號，只要補設角色 |
| 權限 | 訪客可以作答，回答會計入結果；資料上分得出哪些是訪客的，之後可以整批排除 |
| 重複送出 | 不做伺服器端去重；送出鈕在送出中停用並顯示「進入中…」，接受偶發的空訪客帳號 |

角色有部落，和 #145「部落不存在帳號上」不同：#145 的規則只管 among 魚頁，魚島照本文件。

部落在畫面上一律寫「族語（中文）」，例如 yayo（椰油）；對照在 `resources/js/constants/island.js`。

### 3.2 限流

| 動作 | 限制 | 備註 |
|---|---|---|
| 建角色（未登入） | 每個來源每分鐘 5 次，全站合計每分鐘 60 次 | 網站在 Cloudflare 與 Coolify 轉送層後面，連線來源永遠是同一個內部位址，所以以 `CF-Connecting-IP` 計（只在連線來自內部位址時採用） |
| 建角色（已登入） | 每個帳號每分鐘 5 次 | |
| 送出回答 | 每個帳號每分鐘 30 次 | |
| 被限流時 | 顯示「送出太多次了，請等 N 秒再試」並倒數 | `useRateLimitCountdown.js` |

具名限流器都在 `AppServiceProvider`。

### 3.3 作答（#172）

- 可以替任何部落作答。回答算在「角色當下所在的部落」，不是角色自己的部落。
- 每筆回答另外記下回答者自己的部落（`respondent_tribe`，沒有魚島角色的人為空）。
- 作答頁：照片完整不裁切、可以全螢幕放大；三個分頁「叫法／分類／處理」，每個分頁先看結果，按「我來說」再選選項，點選項就送出；沒有「跳過」；下方固定「下一條魚」。
- 網址帶 `question`（name／food_category／processing_method）時一進來停在那一題（#189）。
- 三題：
  - 叫法：選項＝正式魚名＋這個部落已經有人填過的寫法＋「都不對／補充」（打字）。錄音補充見 #175。
  - 飲食分類：`config/fish_options.php` 的 `response_food_categories`。
  - 處理方式：`response_processing_methods`（去魚鱗、不去魚鱗、剝皮、不食用、我不知道）。
- 一次只寫一題（`FishTribeResponse::submitQuestion`），不會清掉其他題；among 魚頁用的 `submit` 行為不變。
- 同一個人、同一條魚、同一個部落只有一筆回答（唯一鍵），可以改。

### 3.4 結果

魚島有兩種「多數」，用途不同：

| 地方 | 規則 |
|---|---|
| 作答頁每一題的結果（#172） | 這個部落這一題有 3 人以上回答，而且第一名人數嚴格多於第二名，第一名標「多數」；平手不標；「我不知道」可以成為多數 |
| 魚卡長條、細節視窗、NPC（#183、#189） | 這個部落這一題筆數最多的選項，平手全部列出（依設定順序），沒有人數門檻；處理方式不算「我不知道」 |

其他規則：

| 顯示的東西 | 規則 |
|---|---|
| 有結果 | 這個部落有分類回答，而且有不是「我不知道」的處理方式回答（`islandHasResultSql`）；只算選項清單裡的值，MySQL 逐位元組比對（大小寫、尾端空白不同都不算） |
| 「我不知道」 | 單一來源是 `fish_options.response_unknown_processing_method` |
| 打字補充的叫法 | 存成一種新寫法，算 1 人，之後的人會在選項裡看到 |
| 人數 | 這個部落這一題所有回答者，不分回答者自己是哪個部落；作答頁另列「其中本部落 N 人」 |
| 誰答的 | 回答者的角色名與他自己的部落；訪客標「訪客」；在 among 答過、沒有魚島角色的人顯示「among 族人」 |
| 細節視窗（「誰說的？」） | 分類、食用兩個分頁；所在部落第一、全島第二、其他部落依人數；長度依人數 |
| 部落進度 | 「{部落} 的魚 X/Y」：這個部落有結果的魚條數／全部未軟刪除的魚條數 |

among 魚頁的畫面不變（只顯示人數，不顯示名字）。訪客的回答會算進 among 魚頁的人數。

### 3.5 家屋、地點與 NPC（#189）

| 項目 | 規則 |
|---|---|
| 四個地點 | 主屋（阿姨）、靠背石（爺爺）、曬魚庭院（叔叔）、涼亭（年輕人），定義在 `App\Support\IslandSpot` |
| 分配 | 魚編號除以 4 的餘數：1＝主屋、2＝靠背石、3＝曬魚庭院、0＝涼亭；新增或刪除魚不會讓其他魚換地點 |
| 地點卡 | 「X/Y 有結果」；Y＝0 時寫「這裡還沒有魚」；點卡＝聊天、「看清單」＝地點清單 |
| 排序（清單與 NPC 共用） | 兩題都有結果 → 一題有結果 → 都沒結果；同組回答筆數多的在前，再依編號 |
| 要問的那一題 | 叫法 → 分類 → 處理方式，第一個缺的（`FishTribeResponse::islandQuestionToAsk`）；清單的「搶先回答／幫它取名」、NPC 的問句與「我來說」都用它 |
| NPC 說的話 | 「這是 {魚名}。我們 {部落} {分類句}；{處理句}。」＋問句；最後一條加「這裡的魚都講完了。」（`App\Support\IslandNpcSpeech`） |
| NPC 外觀 | 第一版是彩色圓形頭像加中文稱呼，虛構角色，不用真人照片、不用 emoji |

## 4. 架構決定

### 4.1 放在哪

沿用現有的 Laravel＋Inertia＋Vue 結構，不另開 Vite 入口、不另開資料夾層級：

```
routes/web.php                              /island 路由群組（不掛 auth、browse）
  /island                                   地圖（Island/Home）
  /island/character                         角色設定（Island/Character）
  /island/tribes/{tribe}                    家屋（Island/Tribe）
  /island/tribes/{tribe}/spots/{spot}       地點清單（Island/Spot）
  /island/tribes/{tribe}/spots/{spot}/talk  NPC 對話（Island/Talk）
  /island/tribes/{tribe}/fish/{id}          作答頁（Island/Fish）
app/Http/Controllers/Island/                IslandController、IslandResponseController
app/Http/Middleware/EnsureIslandCharacter   要有魚島角色
app/Models/IslandCharacter.php              魚島角色
app/Support/IslandSpot.php、IslandNpcSpeech.php
resources/js/Pages/Island/                  魚島的頁面
resources/js/Layouts/IslandLayout.vue       魚島的版面（不共用 among 的導覽列）
resources/js/Components/Island/             IslandMap、FishCardList、ResultBar、ResultDetailDialog、QuestionResult
```

### 4.2 資料

| 資料 | 做法 | 理由 |
|---|---|---|
| 訪客帳號 | `users` 新增一筆：`source = island_guest`、email 與密碼留空 | `fish_tribe_responses.user_id` 必填且有外鍵，訪客要有帳號才能存回答 |
| 魚島角色 | 新表 `island_characters`：帳號、名字、部落；一個帳號一筆 | 不動 `users` 的意義，among 不受影響 |
| 回答 | 沿用 `fish_tribe_responses`，新增 `processing_method` 與 `respondent_tribe` 兩個可空欄位 | among 與魚島看的是同一份資料 |
| 分辨訪客 | 以回答所屬帳號的 `source` 判斷 | 之後要排除訪客數據，篩帳號即可，不用改回答表 |
| 地點 | 不存資料表，由魚編號算 | 不用遷移，魚不會換地點 |

既有唯一鍵（帳號＋魚＋部落）不變，對應「同一人同魚同部落一筆」，所以一筆回答就是一個人。

### 4.3 要沿用的既有程式

- `App\Models\FishTribeResponse`：`submitQuestion`（魚島一次一題）、`sameSpelling`、`islandQuestions`（作答頁）、`islandResultCounts`／`islandHasResultSql`／`islandSpotOrderSql`（魚卡、清單、NPC）。統計都在這裡擴充，不另寫一份。
- `config/fish_options.php`：部落、飲食分類、處理方式、「我不知道」的選項來源。
- 錄音（#175 用）：`FishResponseController` 的上傳流程、`useAudioRecorder.js`、`useAudioPlayback.js`、`RecordingPlayButton.vue`。

### 4.4 地圖

- 手機優先的平面地圖（SVG），6 個部落是可點的點，角色用移動動畫走過去。不引入地圖套件。
- 鍵盤操作：#184 做過 Tab 焦點外框，chung 預期的是方向鍵移動、按 Enter 進入部落，跟做法不同，而且之後的 3D 地圖用不到，所以移除（未 merge）。方向鍵操作留到 3D 地圖一起設計。
- 平板與電腦的 3D 地圖之後再做（參考 puma.taipei/heart-island）。

### 4.5 畫面風格

海島遊戲感，和 among 的博物誌風格分開：藍色的海、綠色的島、白底圓角卡片、橘色重點（主要按鈕、目前位置、多數）。字級與按鈕高度沿用 among 的長者規格。色碼與元件寫在 `design-spec.md` 的魚島一節；結果長條的配色與地點代表色在 `resources/js/constants/island.js`。chung 重視「看圖不看字」與「先看結果、自己挑」：結果用堆疊長條，不用 emoji 圖示。

## 7. 風險與待觀察

- 訪客不用登入就能寫入：建角色與送出回答都有限流；訪客數據可整批排除（見 4.2）。
- 訪客清掉瀏覽器資料後再來，會變成另一個帳號，同一個人可能被算成兩人。LINE 合併上線前先接受這個誤差。
- 魚島讓沒登入的人看得到各部落的說法，和 among 魚頁（要登入）不同，這是刻意的；回答者名字只顯示他自己取的角色名。
- 部署切換分支時，新容器啟動前會有短暫 504（Cloudflare 錯誤頁會直接彈出，見 #197）。實測分支用的是正式站與正式資料庫，測完要切回 develop。
