# 魚島（Island）設計文件

狀態：整體架構雛形（2026-11-24 確認）。父 issue：#169。細節規格寫在各子 issue，本文件只記問題、解法、切分，以及跨 issue 都要遵守的決定。

## 1. 問題

- 族人對同一條魚的叫法、飲食分類、處理方式，各部落不一樣，而且沒有標準答案。
- among 魚頁的「大家怎麼說」（`fish_tribe_responses`）已經能收各部落的說法，但要先登入、要先找到那條魚、一次只看一條魚，願意來填的人不多。
- 沒有登入的人完全看不到「大家怎麼說」，也沒有理由留下來。

## 2. 解法

在同一個網站開一個不用登入的新前端「魚島」（`/island`）：

1. 進來先設一個角色（名字＋部落），就能開始玩。
2. 畫面是蘭嶼的平面地圖，上面有 6 個部落。角色從自己的部落出發，點哪個部落就走到哪裡。
3. 到了一個部落，看到魚卡。每條魚三題：叫法、飲食分類、處理方式。
4. 沒有標準答案。答完看到這個部落目前「多數人怎麼說」和每個選項有誰答過。

回答寫進 among 現有的同一張表，among 魚頁的「大家怎麼說」會跟著增加。

## 3. 已確認的規則

### 3.1 身分

| 項目 | 規則 |
|---|---|
| 入口 | `/island`，不用登入 |
| 角色 | 名字＋部落，一個帳號一個角色。名字就是顯示給別人看的名字，想匿名就取暱稱 |
| 訪客 | 沒登入的人設好角色後，系統替他建一個「魚島訪客」帳號，靠瀏覽器記住。清掉瀏覽器資料就找不回這個角色 |
| 已登入 among 的人 | 用原本的帳號，只要補設角色 |
| 權限 | 訪客可以作答，回答會計入結果；資料上分得出哪些是訪客的，之後可以整批排除 |

角色有部落，和 #145「部落不存在帳號上」不同：#145 的規則只管 among 魚頁，魚島照本文件。

### 3.2 作答

- 可以替任何部落作答。回答算在「角色當下所在的部落」，不是角色自己的部落。
- 每筆回答另外記下回答者自己的部落（沒有魚島角色的人為空）。
- 三題：
  - 叫法：選項＝正式魚名＋這個部落已經有人填過的寫法＋「都不對／補充」。補充可以打字或錄音。
  - 飲食分類：沿用 `config/fish_options.php` 的 `response_food_categories`。
  - 處理方式：去魚鱗、不去魚鱗、剝皮、不食用、我不知道。
- 同一個人、同一條魚、同一個部落只有一筆回答，可以改。

### 3.3 結果

| 顯示的東西 | 規則 |
|---|---|
| 多數 | 這個部落這一題有 3 人以上回答，而且第一名人數嚴格多於第二名，第一名標「多數」 |
| 平手 | 不標多數，只列各選項人數 |
| 不到 3 人 | 顯示「人數還不夠」與目前人數，不標多數 |
| 我不知道 | 是一個正常選項，可以成為多數 |
| 打字補充的叫法 | 存成一種新寫法，算 1 人，之後的人會在選項裡看到 |
| 只有錄音、沒有打字 | 不列入叫法的人數統計 |
| 人數 | 這個部落這一題所有回答者，不分回答者自己是哪個部落；旁邊另列「其中本部落 N 人」 |
| 誰答的 | 每個選項底下列出回答者的角色名與他自己的部落；訪客在名字旁標「訪客」 |
| 在 among 答過、沒有魚島角色的人 | 人數照算，名字顯示「among 族人」，不顯示帳號名稱 |
| 錄音 | 訪客第一版不能播放別人的錄音；自己的可以 |

among 魚頁的畫面不變（只顯示人數，不顯示名字）。訪客的回答會算進 among 魚頁的人數。

## 4. 架構決定

### 4.1 放在哪

沿用現有的 Laravel＋Inertia＋Vue 結構，不另開 Vite 入口、不另開資料夾層級：

```
routes/web.php                         新增 /island 路由群組（不掛 auth、browse）
app/Http/Controllers/Island/           魚島的控制器
app/Http/Middleware/                   新增「要有魚島角色」的檢查
app/Models/IslandCharacter.php         魚島角色
resources/js/Pages/Island/             魚島的頁面
resources/js/Layouts/IslandLayout.vue  魚島的版面（不共用 among 的導覽列）
resources/js/Components/Island/        魚島的元件
```

### 4.2 資料

| 資料 | 做法 | 理由 |
|---|---|---|
| 訪客帳號 | `users` 新增一筆：`source` 為魚島訪客專用值、`role` 為 `guest`、email 與密碼留空 | `fish_tribe_responses.user_id` 必填且有外鍵，訪客要有帳號才能存回答；`guest` 本來就進不了 among 要登入的頁面 |
| 魚島角色 | 新表 `island_characters`：帳號、名字、部落；一個帳號一筆 | 不動 `users` 的意義，among 不受影響 |
| 回答 | 沿用 `fish_tribe_responses`，新增「處理方式」與「回答者自己的部落」兩個可空欄位 | among 與魚島看的是同一份資料 |
| 分辨訪客 | 以回答所屬帳號的 `source` 判斷 | 之後要排除訪客數據，篩帳號即可，不用改回答表 |

既有唯一鍵（帳號＋魚＋部落）不變，剛好對應「同一人同魚同部落一筆」。

### 4.3 要沿用的既有程式

- `App\Models\FishTribeResponse`：`submit`（寫入與並發處理）、`sameSpelling`（同一種寫法的判斷）、`summaryForFish`（各部落彙總）。魚島的多數判定與「誰答的」在這裡擴充，不另寫一份統計。
- `App\Http\Controllers\FishResponseController`：錄音上傳網址與暫存檔搬移的流程。
- `resources/js/composables/useAudioRecorder.js`、`useAudioPlayback.js`，`resources/js/Components/FishResponses/RecordingPlayButton.vue`。
- `config/fish_options.php`：部落、飲食分類、處理方式的選項來源。

注意：`FishTribeResponse::submit` 目前把「沒帶的欄位」視為清空（錄音除外）。魚島若一題一題送出，會把其他題清掉；#172 的決定是作答頁整筆一起送；among 魚頁送出時不改動新增的兩個欄位。

### 4.4 地圖

- 第一版：手機優先的平面地圖（SVG），6 個部落是可點的點，角色用移動動畫走過去。不引入地圖套件。
- 平板與電腦的 3D 地圖之後再做，不在第一版。

## 7. 風險與待觀察

- 訪客不用登入就能寫入：建立訪客帳號與送出回答都要限流；訪客數據可整批排除（見 4.2）。
- 訪客清掉瀏覽器資料後再來，會變成另一個帳號，同一個人可能被算成兩人。LINE 合併上線前先接受這個誤差。
- 魚島讓沒登入的人看得到各部落的說法，和 among 魚頁（要登入）不同，這是刻意的；回答者名字只顯示他自己取的角色名。
